# Voice2Prompt 需求规格（用例体）

状态：**v2 待审**（§9 用例补丁，审过后再动工）  
范围：反「直接回答」加固 · 按需提示词处理 · 全局选中浮条 · 语音预览卡 · 设置项 · 内存约束  
不含：皮肤/画板（另一工作树负责，本规格不涉及）

> 阅读顺序：§9 为本轮增量（交互重构 + 限源触发 + 思考模式 + 性能证据）；§1–8 为上一轮已实现基线，与 §9 冲突处 **以 §9 为准**。

## 1. 背景与目标

### 1.1 要解决的问题

1. **语音被当成问题直接回答**：口述若是完整问句，模型会作答而不是改写成 prompt。  
2. **手写 prompt 的人缺少「选中即优化」**：Typeless/Openless 管语音；coding 时手写草稿缺一个跨应用的「优化提示词 / 结构化提示词」动作。  
3. **是否过模型应由用户控制**：短句纯转写省 token；需要时再结构化/优化。

### 1.2 产品定位

| 入口 | 角色 | 说明 |
|------|------|------|
| 全局选中浮条 | 主卖点（蓝海） | 任意应用拖选 → 浮条 → 优化/结构化 |
| 语音听写 | 原有主路径 | 说话 → 转写 → 可选处理 → 写入光标 |
| 桌宠 BongoCat | 触发与状态 | 录音、模式标记、气泡提示 |

## 2. 术语

| 术语 | 含义 |
|------|------|
| **不处理** | 不调用大模型，文本原样使用（纯转写/原选区） |
| **仅结构化** | 调用大模型，只做断句、标点、去口头语、编号整理，不补业务要素 |
| **提示词优化** | 调用大模型，补全角色/约束/输出格式等，产出可投喂的结构化 prompt |
| **选中浮条** | 鼠标拖选文字后，在光标附近出现的轻量操作条 |
| **语音预览卡** | 语音转写完成后、写入光标前，可编辑并选择处理方式的卡片 |
| **替换选区** | 用处理结果覆盖当前选中的文字 |
| **写入光标** | 把文本粘贴到当前光标位置 |

## 3. 全局约束

### 3.1 内存（硬约束）

| 约束项 | 要求 |
|--------|------|
| 选中浮条渲染进程 | 常驻 ≤ 20MB |
| 浮条技术栈 | 纯 HTML/CSS/JS，禁止 Live2D / Pixi / 皮肤贴图 / 完整设置页 |
| 浮条窗口数量 | 全局仅 1 个，隐藏复用，禁止多实例 |
| 文本缓存 | 只保留「当前选中/转写」与「上一次原文」，不做历史列表 |
| 合入门禁 | 附空闲/弹出/处理三态工作集测量 |

### 3.2 不干扰正常使用

- 浮条/预览卡不抢键盘焦点（`showInactive` / 无焦点窗）。
- 点击浮条外部、按 Esc、点关闭 = 无操作消失，不修改任何文本。
- **绝不自动调用大模型**，必须用户点击按钮才处理。
- 录音进行中不弹选中浮条。

### 3.3 仓库边界

- 不改皮肤/画板相关文件（`paint.*`、`assets/paint_kit`、皮肤模型目录）。
- 每完成一步 `git commit`，直接提交 `main`。
- `.gitignore` 忽略依赖、打包产物、截图、Live2D 专有运行时、密钥/IDE 文件。

## 4. 用户可选配置（设置页 Checkbox）

> 下列全部是设置项，默认值已锁定。用户可随时勾选/取消。

### 4.1 处理强度

| 配置项（界面文案） | 配置键 | 默认 | 说明 |
|--------------------|--------|------|------|
| ☐ 结构化整理：把口语/草稿组织成清晰分节与编号 | `enableStructure` | **不勾** | 与优化同时开时，优化含结构 |
| ☐ 提示词优化：补全角色/约束/输出格式等要素 | `enableOptimize` | **不勾** | 勾选后走优化提示词 |
| ☐ 启用语音预览卡：转写后先预览再写入 | `previewEnabled` | **不勾** | 不勾 = 说完直接按上面两开关处理 |

**默认处理模式**：两开关都不勾 = **不处理**（纯转写/原样）。勾任一 = 对应处理。无独立第三开关。

### 4.2 选中浮条回写

| 配置项 | 配置键 | 默认 | 说明 |
|--------|--------|------|------|
| ☐ 仅复制到剪贴板，不替换选中文字 | `writeBackCopyOnly` | **不勾** | 不勾 = 替换选区；勾 = 仅复制 |
| ☐ 处理后恢复原来的剪贴板内容 | `clipboardRestore` | **不勾** | 不勾 = 结果留在剪贴板（顶掉原内容）；勾 = 恢复 |

**组合规则（防结果丢失）**：勾选「仅复制」时，**强制不恢复**原剪贴板（结果必须留在剪贴板），浮条提示「结果已复制到剪贴板」；「恢复原来的剪贴板」仅在「替换选区」模式下生效。

### 4.3 触发与阈值

| 配置项 | 配置键 | 默认 | 说明 |
|--------|--------|------|------|
| ☐ 启用选中浮条 | `paletteEnabled` | **勾选** | 总开关 |
| 选中字数低于该值不弹浮条 | `paletteMinChars` | `8` | 数字输入 |
| 选中超过该字数提示「建议进 App 处理」（仍可点按钮处理） | `paletteLongHint` | `8000` | **2000 字完全可处理、不提示**；超长只是防卡顿提示，**不阻断**（模型输入可到很长，远超 2000 字） |
| 语音预览卡：少于该字数跳过预览直接写入 | `previewSkipChars` | `12` | 仅预览卡开启时生效 |

### 4.4 兼容保留

| 配置项 | 说明 |
|--------|------|
| 语音写入方式 `insertMode`（粘贴到光标 / 仅复制） | 与「选中回写」分组，互不影响 |
| 自定义优化提示词 `promptText` | 保存时强制校验含「禁止回答」类红线；缺失则自动补注入 |

## 5. 用例

### 用例 UC-01：选中文字后优化或结构化提示词

| 项 | 内容 |
|----|------|
| 主执行者 | 手写 prompt 的用户（coding / 对话框 / 文档） |
| 前置条件 | 选中浮条已启用；已配置文字（LLM）模型；当前未在录音 |
| 保证 | 不点按钮绝不改文本、绝不调模型；点「×」/浮条外/Esc = 关闭且零副作用 |

**主成功场景（两键）**

1. 用户在任意应用中按住左键拖选一段文字（拖动距离 ≥ 8px）。  
2. 系统模拟复制读取选中文本（先记录当前剪贴板）。  
3. 光标附近弹出**选中浮条**（不抢焦点）：`优化提示词 | 结构化整理 | ⋯ | ×`  
4. 用户点击「优化提示词」。  
5. 系统调用大模型做提示词优化（含输出校验与降级，见 UC-03）。  
6. 按回写设置：默认**替换选区**；若勾选「仅复制」则只进剪贴板。  
7. 浮条显示短暂结果提示后关闭。

**扩展**

- **3a. 点击「结构化整理」**：走仅结构化，同步骤 6–7。  
- **3b. 点击「⋯」**：展开「复制原文 / 打开 Voice2Prompt 设置 / 功能反馈」。  
- **3c. 点击「×」、点浮条外、按 Esc**：关闭浮条，不处理。  
- **2a. 选中字数 < 阈值（默认 8）**：不弹浮条。  
- **2b. 拖动距离 < 8px**：不弹浮条。  
- **2c. 正在录音**：不弹浮条。  
- **2d. 目标进程在排除列表**：不弹浮条。  
- **2e. 检测到用户自行 Ctrl+C 复制（约 300ms 内）**：不弹浮条。  
- **2f. 选中超过长文阈值（默认 8000 字）**：浮条显示「较长，建议进 App 处理」，**仍可**点优化/结构化；2000 字以内不提示。  
- **6a. 替换失败**：退化为写入剪贴板，并提示「已复制，请手动粘贴」。  
- **6b. 若勾选「处理后恢复原来的剪贴板」且为替换选区模式**：流程结束后恢复步骤 2 记录的剪贴板。  
- **6c. 若勾选「仅复制」**：结果必须留在剪贴板，**不执行**恢复（避免结果被覆盖丢失）。

**验收标准**

- [ ] 拖选后出现浮条，不打断输入焦点  
- [ ] 点「优化提示词」才产生 LLM 调用；点 ×/外部/Esc 无调用、文本不变  
- [ ] 默认替换选区；勾选「仅复制」后只进剪贴板  
- [ ] 问句选中优化后不出现「答案」，只是 prompt/整洁问句  
- [ ] 2000 字内不弹长文提示；超长有提示但不阻断  
- [ ] 「仅复制」+「恢复剪贴板」同时勾选时，结果仍在剪贴板可取  
- [ ] 浮条进程工作集 ≤ 20MB（空闲隐藏时测量）

### 用例 UC-02：语音听写并按需处理后写入光标

| 项 | 内容 |
|----|------|
| 主执行者 | 用语音输入的用户 |
| 前置条件 | 已配置 ASR；已配置 LLM（若需处理） |

**主成功场景**

1. 用户通过全局热键 / 鼠标侧键 / 猫身触发录音。  
2. 结束录音，系统转写为文本。  
3. **若未启用语音预览卡**（默认）：  
   - 两处理开关都不勾 → 原文写入光标（不处理）；  
   - 勾了结构化或优化 → 调用对应整理后写入。  
4. **若启用了语音预览卡**：弹出预览卡，显示可编辑原文，按钮：`不处理 | 结构化整理 | 优化提示词` + `写入光标 | 仅复制`。  
5. 用户选择后执行；短句（默认 < 12 字）可跳过预览直接写入（设置可调）。

**扩展**

- **3a/5a. 转写为空**：提示「没有识别到语音内容」。  
- **处理失败**：见 UC-03 降级。  
- **与浮条并发**：录音中不弹选中浮条。

**验收标准**

- [ ] 默认无预览卡，说完直接写入  
- [ ] 设置勾选「启用语音预览卡」后出现预览，且原文可编辑  
- [ ] 预览卡选「不处理」= 纯转写  
- [ ] 短句跳过阈值可配置

### 用例 UC-03：防止模型把口述/草稿当成问题直接回答

| 项 | 内容 |
|----|------|
| 主执行者 | 系统（整理层） |
| 触发 | 任一路径选择了「结构化整理」或「优化提示词」 |

**主成功场景**

1. 系统使用**硬化后的整理提示词**（角色=文本重写器，不是助手）。  
2. 输入若为疑问句，只改写成提问型 prompt，**禁止输出答案**。  
3. 输出经过本地启发式校验：  
   - 含「好的/当然/以下是」等开场白；  
   - 输出相对输入异常膨胀（> 2.5 倍）；  
   - 出现代码块包裹；  
   - 明显在直接回答「是什么/为什么/怎么做」。  
4. 命中则用更硬约束**重试 1 次**。  
5. 仍失败 → 降级为**仅结构化**。  
6. 再失败 → 降级为**原文**，并提示「已降级为原文」。

**验收标准**

- [ ] 问句「什么是××？」优化后无答案正文  
- [ ] 「帮我写周报…」优化后无周报成品  
- [ ] 违规输出会被重试或降级，而不是直接写入

### 9.0 本轮要什么（一句话）

1. 结构化/优化都要有**可区分**的桌宠底部文字条反馈，字号更大  
2. 悬浮条改**竖排、更小、白底黑字**，结构化优先、优化次之，处理过程有动画

### 9.1 用例 UC-V2-A：处理完成后的桌宠反馈（底部文字条）

| 项 | 内容 |
|----|------|
| 主执行者 | 用户 |
| 前置 | 点了「结构化」或「优化」，或语音走完处理 |
| 需求 | 桌宠**底部文字条**（非气泡冒泡式临时泡，而是底部条）展示结果摘要/状态 |

**主成功场景**

1. 用户触发「结构化整理」。  
2. 处理中：桌宠底部文字条进入 **结构化·运行中**（样式 A）。  
3. 成功：底部文字条变为 **结构化·完成** + 结果摘要（样式 A′）。  
4. 若是「提示词优化」：运行中 / 完成用 **样式 B / B′**（与 A 明显不同）。

**状态分离（必须一眼可辨）**

| 状态 | 建议表现（可调） | 文案前缀 |
|------|------------------|----------|
| 结构化·运行中 | 底部条，主色系 1（如青/灰蓝），转圈或进度点 | `结构化中…` |
| 结构化·完成 | 同主色 1，显示 `结构化完成` | `结构化完成` |
| 优化·运行中 | 主色系 2（如琥珀/紫），样式与 1 不同 | `优化中…` |
| 优化·完成 | 主色 2 | `优化完成` |
| 降级/失败 | 警示色，写明降级到哪一级 | `已降级为…` |

**字号**

- 底部文字条字号 **≥ 现状态条一档**（例如 12px → **14–16px**），保证桌宠旁可读。

**验收标准**

- [ ] 结构化与优化的底部条颜色/文案不同  
- [ ] 运行中与完成状态可区分  
- [ ] 字号明显大于现状  
- [ ] 不用「只弹一下就消失的小气泡」代替底部文字条

### 9.2 用例 UC-V2-B：选中浮条 UI 重构（竖排极简）

| 项 | 内容 |
|----|------|
| 主执行者 | 用户 |
| 前置 | 触发条件满足（见 UC-V2-C，**仅输入区文本**） |

**布局**

```
┌────────────┐
│ ≡ 结构化   │  ← 默认首选，置顶
│ ✨ 优化提示词 │  ← 次选
│ ⋯          │  ← 更多（可选）
│ ×          │  ← 关闭=不处理
└────────────┘
```

| 项 | 规格 |
|----|------|
| 形态 | **列状（竖排）**，整体更小 |
| 配色 | **白底黑字**，极简；无大色块按钮（可仅细边/浅灰选中态） |
| 顺序 | **结构化输出在上**；提示词优化在下 |
| 交互 | 点选才处理；×/点外/Esc = 不处理 |

**处理过程交互动画（必做）**

| 阶段 | 浮条表现 |
|------|----------|
| 点击后立即 | 按钮变为该动作名 + **运行指示**（转圈/脉动/进度点），另一按钮禁用 |
| 请求发出 | 可显示 `等待模型…` |
| 完成 | 短暂 `完成` 后关闭；或显示失败/降级原因 |

**验收标准**

- [ ] 竖排、白底黑字、比现在更小  
- [ ] 第一项是结构化，第二项是优化  
- [ ] 点击后浮条上有明确「运行中」动画直到结束

### 9.3 用例 UC-V2-C：只对「输入中的文本」弹条（限源）

| 项 | 内容 |
|----|------|
| 目标 | **禁止**对聊天记录、网页正文、桌面、只读文档、终端等非输入文本弹出 |

**判据（实现可组合，先定原则）**

仅当同时满足才弹：

1. 选中来自**可编辑区域**（输入框 / textarea / contenteditable / 代码编辑器的可编辑 buffer），或应用在「写作/输入」白名单且当前焦点是编辑控件；  
2. 不是桌面/系统菜单/只读页面纯选中；  
3. 非终端进程（上一版已排除的继续排除）。

**明确禁止弹出（与截图对齐）**

- 聊天/评审/日志里的**历史消息**选中  
- 浏览器只读正文

### 9.4 性能：输出过久排查（证据，非猜测）

**疑点**：结构化/优化等待过久。

**代码证据**

1. **思考模式默认不关（非小米域名）** — `models.js`：

```js
function shouldDisableThinking(provider) {
  if (provider.noThinking === true) return true;
  if (provider.noThinking === false) return false;
  return /xiaomimimo/i.test(provider.baseUrl || ''); // 仅 MiMo 自动关
}
```

- `noThinking` 为 `undefined` 且 **Base URL 不是小米 MiMo** → **不会**发 `thinking=disabled` / `reasoning_effort=none`。  
- 混合推理模型（开思考）会先生成 reasoning tokens，注释自记 **4~8s**。  
- **结构化与优化共用同一 `chatCompletion`**，思考开关只跟 **provider** 走，**没有**「结构化关思考 / 优化开思考」的分模式配置。

2. **请求非流式，整段等完** — `models.js`：`stream: false`，用户无法看到中间输出，体感「卡住」。

3. **如何取证（实现后/现在也能看）**  
   日志行：`[llm] 1118ms completion_tokens=2 reasoning=0`  
   - `reasoning>0` → **思考模式在跑**（实锤）  
   - `reasoning=0` 仍慢 → 看 `completion_tokens` 是否爆炸（校验重试）或网络

4. **「疑似只接了提示词优化」**  
   - 设置页两开关：勾「结构化」不勾「优化」时，**语音默认**应走 structure。  
   - 但 **浮条按钮是显式 mode**，点「优化」一定走优化提示词（更长 system + 要素补全，更慢）。  
   - 若 UI 文案/默认顺序让人误点优化 → 会误以为「只有优化」。v2 浮条已把 **结构化置顶**。

**设置页（截图需求）**

- 「思考模式」控件挪到「结构化 / 提示词优化」checkbox **同组旁**。  
- **结构化、优化各一个**思考选项（可自动/关/开），默认建议：**结构化=关思考**，**优化=关思考（若模型质量不够再对优化单独开）**。

| 配置项（文案） | 默认 | 说明 |
|----------------|------|------|
| ☐ 结构化：强制关闭思考模式 | 勾选 | 优先速度 |
| ☐ 提示词优化：强制关闭思考模式 | 勾选 | 优先速度 |
| （回退）provider 级 `noThinking` | 自动 | 与上两项叠加：任一「关」即关 |

**验收标准**

- [ ] 能用日志证明 reasoning 是否为 0  
- [ ] 结构化/优化可**分别**控制思考  
- [ ] 控件在两 checkbox 附近，不在 provider 列表深处
