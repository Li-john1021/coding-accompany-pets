## 1. 交付目标与范围

交付两条独立、可连续使用的操作链路：

```text
Alt+A / 点击截图 → 鼠标框选 → 图片自动进入剪贴板
点击识图 → 当前多模态模型转写 → 文字自动进入剪贴板
```

1. 默认截图全局热键为 `Alt+A`；设置页可修改并持久化，软件失焦或仅托盘常驻时也能触发。
2. 每个文字模型配置有独立的“多模态”勾选项；使用当前选中的模型及其声明能力。
3. 识图支持本软件截图和其他软件复制的实际图片；文件路径、图片 URL 或只有文件列表的剪贴板不等同于图片内容。
4. 优先转录原文并保持必要结构；图表和无文字图片补充客观描述。保留原语言，不自动翻译，不回答图内问题。
5. 识图成功后写文字剪贴板。后续纯文本模型可以消费这些文字；本功能不自动启动第二次模型分析或文本优化。
6. 识图复用 MarkItDown 的内部视觉服务模式，在现有 JavaScript 请求层实现；本版不依赖 Python MCP 服务进程、本地 OCR 或模型训练。
7. 本版不扩展滚动长截图、截图标注编辑、批量文件解析或识图快捷键。

## 2. 已确定的交互合同

### 截图

- 点击截图和全局快捷键调用同一截图入口。
- 框选时展示冻结的屏幕画面及选区；确认后将裁剪图片以 PNG 写入系统剪贴板。
- `Esc` 取消、零面积选区、捕获失败均不写剪贴板，并释放截图窗口与忙碌状态。
- 重复触发不创建第二套框选窗口。
- 处理多屏坐标、负坐标和不同 DPI；跨屏选区按各屏实际像素裁剪后映射到统一输出尺度合成，不直接用逻辑坐标裁图。
- 捕获前暂时隐藏需要排除的本应用悬浮窗口；成功、取消、异常后恢复此前可见性，避免重新显示用户原先隐藏的窗口。

### 识图及按钮

- 新增截图按钮；启用现有识图占位按钮，操作区共四个按钮：结构化、优化、截图、识图。
- 初始化时识图按钮禁用，完成首次能力和剪贴板检查后再按条件更新。
- 启用条件：当前文字模型配置完整、`multimodal === true`、剪贴板存在非空实际图片、没有冲突操作。
- 识图点击时主进程再次验证条件，冻结本次图片和 provider 配置；请求中切换模型或复制新图片不改变本次输入。
- 显示“识图中”及成功/失败反馈；同一时间最多一个截图或识图操作，并与现有录音、文本处理、预览和结果写入状态协调。
- 成功时将本次转写正文写入剪贴板；按既有成功结果交付约定，即使等待期间发生其他复制，本次成功仍发布结果。失败时不主动清空或恢复剪贴板，不覆盖用户等待期间复制的新内容。
- 写入文字后重算按钮状态；剪贴板已无图片时禁用识图。其他软件复制图片、保存设置、切换模型后也要更新。
- 识图结果仅复制，不走现有自动粘贴、选中文字捕获、结构化、优化或撤销结果交付路径。

### 热键和配置

- 保留现有录音热键，另存 `screenshotHotkey`；旧配置缺字段时取 `Alt+A`。
- 旧模型缺 `multimodal` 时按 false 处理，不根据模型名字猜测能力。
- 设置页的快捷键录制器可编辑录音或截图字段；录制期间暂停相关全局触发，结束或关闭设置窗后完整恢复。
- 录音/截图热键重复、格式错误、被其他程序占用时显示具体错误；不能显示“已保存成功”却实际未注册。注册失败恢复之前有效的热键配置及监听。
- 多模态勾选声明不等于服务支持。当前文字 ping 校验继续区分于图片校验；需要用户主动校验时，对已勾选模型执行小图片探测，不能在启动或轮询时自动发模型请求。

## 3. 模块与接口安排

下列新增文件名称为实施建议，可以按现有结构作小幅调整，职责与边界保持一致。

| 模块 | 改动或新增文件 | 职责 |
|---|---|---|
| 配置 | `app/main/config.js`、`app/renderer/settings.js`、`settings.html`、`styles.css` | 新字段默认值、模型行勾选、读写持久化、截图热键录制与错误呈现 |
| 热键 | `app/main/main.js`；建议提取 `app/main/global-hotkeys.js` | 注册、校验、恢复两套热键，覆盖启动、保存设置、关闭设置和录制结束 |
| 截图 | 新增 `app/main/screenshot.js`、`app/renderer/screenshot.html`、`screenshot.js` | 屏幕捕获、框选窗口生命周期、坐标/像素映射、裁剪合成、PNG 写入 |
| 视觉模型 | `app/main/models.js`；新增 `app/main/vision-prompts.js` | `transcribeImage(provider, pngBuffer, opts)`、图片校验、独立提取提示词、正文处理 |
| 工作流 | 新增 `app/main/image-workflow.js`，接入 `main.js` | 图片快照、能力检查、互斥、请求生命周期、状态及成功写剪贴板 |
| 主进程桥 | `app/preload.js`、`app/main/main.js` | 截图、识图、能力状态的受限 IPC；只向 UI 返回状态和必要结果 |
| 桌宠按钮 | `app/renderer/pet.html`、`pet.js`、`app/main/pet-window-layout.js`（如需） | 四按钮布局、动作分发、能力变化与忙碌状态，不让点击冒泡为录音手势 |

建议 IPC：`v2p:screenshot`、`v2p:recognize-image`、`v2p:get-image-state`、`v2p:image-state`。按钮和热键共用主进程工作流；渲染层不自行发模型请求。

图像读取使用 Electron 31 的 `clipboard.readImage()`；非空图片转 PNG。图文消息采用 `text` 与 `image_url` 内容块，图片为内嵌 Data URI。复用现有 URL 拼接、Key 解码和鉴权约定。

请求只生成一次转写结果，沿用当前请求的有界超时；超时、鉴权/格式错误、服务不支持图片和空正文均明确失败。只读取最终正文，不回退到 reasoning 内容。以 `trim()` 判断空白，但不得直接裁掉正文开头的代码缩进。应用退出后取消未完成请求，迟到结果不得继续写剪贴板。

## 4. 实施阶段与完成标准

| 顺序 | 工作项 | 完成标准 |
|---|---|---|
| P1 | 配置与设置页 | 多模态标记按模型保存；截图热键默认及自定义值在保存、重开设置、重启后正确回显；原有配置保留 |
| P2 | 全局热键管理 | 录音与截图各触发对应操作；所有重新注册路径恢复两项；冲突可见且不会破坏原有效热键 |
| P3 | 框选截图与图片复制 | 按钮/热键共用入口；可框选、取消及重试；剪贴板获得实际 PNG；多屏和 DPI 场景正确 |
| P4 | 视觉转写服务 | 按 MarkItDown 模式形成图文请求；独立提示词与正文校验；图片校验与文字 ping 区分；失败不发布 |
| P5 | 识图工作流与按钮联动 | 四按钮布局可用；剪贴板图片和模型能力共同控制识图；外部复制、模型切换、忙碌及成功后状态正确 |
| P6 | 回归、Windows 实测及交付 | 下方验收矩阵通过；记录实际模型、屏幕环境、测试结果和未覆盖条件，形成测试报告 |

按 P1 → P2 → P3 → P4 → P5 → P6 推进，每阶段完成其验证再接下一阶段。P3/P4 的底层实现可以分别验证，但最终用同一 P5 工作流集成，不产生两套状态源。

## 5. 验收矩阵

| 编号 | 场景 | 通过条件 |
|---|---|---|
| A01 | 默认/自定义热键，应用在前台、失焦和托盘状态 | 正确打开截图；录音热键仍只负责录音 |
| A02 | 保存、重开/关闭设置、快捷键录制、重启 | 两个快捷键均按最终配置恢复，模型多模态勾选持久化 |
| A03 | 热键与录音重复、被其他软件占用 | 明确报错，不虚报成功，原有效热键可继续使用 |
| A04 | 单屏框选、Esc、零面积、连续重复触发、捕获异常 | 选区图片正确；取消/失败零剪贴板写入；没有遗留遮罩或永久忙碌 |
| A05 | 副屏负坐标、不同缩放、跨屏框选 | 选区位置与像素对应，不偏移、不丢边；合成图片内容正确 |
| A06 | 已有图片、其他软件新复制图片、图片改成文字 | 正确检测实际图片；识图按钮随条件启用/禁用 |
| A07 | 未配置模型、未勾选、已勾选，保存与切换模型 | 仅完整的当前多模态配置允许识图；不能只凭模型名启用 |
| A08 | 点击后复制新图片或切换模型 | 本次请求仍使用启动时的图片和模型快照，完成后按合同发布文字 |
| A09 | 录音/转写、结构化/优化、预览或结果写入时触发新功能 | 按统一忙碌规则提示或拒绝，不误录音、不重复写结果，不让迟到状态覆盖新操作 |
| A10 | 成功、空正文、只有推理、HTTP 错误、超时、图片不支持 | 只有成功且有正文写文字；错误可见且恢复可用状态 |
| A11 | 纯中文/中英小字、数字随机串、代码、表格 | 转录原文，必要结构保留，代码缩进不被统一 trim 破坏；逐样本记录错误 |
| A12 | 图表、无文字图片、图内包含问题/指令 | 输出客观图像信息，区分文字与描述，不回答或执行图内指令 |
| A13 | 自动粘贴设置开/关，新增按钮的点击/滚轮/缩放 | 识图均仅写剪贴板；既有录音/文字行为正常；四按钮可见可点 |
| A14 | 关闭应用、退出截图、异常后重试 | 清理窗口、定时器和请求；退出后无迟到剪贴板写入 |

字符准确率和耗时不编造统一达标数值：为同一批真实截图保存预期文字、实际输出、差异及耗时。数字/代码出现错误不能用“整体描述正确”掩盖；出现明显问题时修复或明确记录模型限制。

## 6. 验证方法与回归范围

1. 对真实易错逻辑做小范围单元验证：双热键冲突/恢复、跨屏坐标和合成尺度、图片请求与最终正文、工作流互斥和异常清理。不为简单样式或字段堆实现镜像测试。
2. 用模拟视觉服务验证请求确有图片、只发一次、错误不写剪贴板、输入快照及按钮状态变化；这些检查不能代替真实识图效果验证。
3. 用真实 Electron/Windows 系统剪贴板验证框选图片和结果文本。保存必要截图证据；图片视觉检查确认裁剪和 DPI 正确，不能只检查 PNG 非空。
4. 使用用户已配置的可用视觉模型，主动执行有限数量的代表性截图验证，记录模型和图片尺寸；只有真实调用通过才声明该模型兼容。无法调用时交付仍注明该部分未验证，不用 mock 冒充实测。
5. 更新 `pet-actions-ui.unit.test.js` 中“三个按钮/识图永久禁用”的旧断言为新行为，保留原按钮及手势保护。针对改动运行 `models-thinking.unit.test.js`、`pet-window-layout.unit.test.js`、`pet-action-renderer-epoch.unit.test.js`、相关工作流及设置检查；集成阶段选择现有 v5 设置与运行时用例回归语音、结构化、优化、自动粘贴和撤销。
6. 常规检查通过后，只因新增修改、失败或尚未解决的问题扩大复测；本版不修改历史 v5/v6 冻结文档来掩盖回归。
